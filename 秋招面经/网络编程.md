## 套接字socket

- 创建一个服务器的起手几步一般都是先创建一个监听套接字，套接字可以理解为一根管道，用于连接服务器和客户端，数据就在其中传输。以cpp为例，常用库有：sys/types.h、sys/socket.h、netinet/in.h、arpa/inet.h等
普通的套接字调用
```socket(int domain, int type, int proto)```
 即可创建，三个参数说明如下：domain是地址族，常用的如ipv4、ipv6、unix域套接字；type是类型，一般来说tcp用sock_stream（字节流），udp用sock_dgram（数据报）；proto一般填0即可，默认协议。
 
 
- 创建套接字后服务端还需要绑定到本机的ip:port上，然后开始监听连接，绑定使用
```bind(int sockfd, const struc sockaddr *addr, socklen_t len)```
函数，bind需要传入的参数第二项是ip:port的描述，通过sockaddr_in这个结构体来描述地址结构，里面主要三个字段sin_family表示地址族，sin_port表示端口，sin_addr.s_addr表示地址，一般使用ipv4下，地址族使用af_inet，地址使用inaddr_any来表示监听本机所有接口，当然也可以使用127.0.0.1回环地址表示用于只监听本机，而填写端口号时，一般还需要调用一下 htons() 函数，用于大小端序的转换。此外也顺便提一嘴，地址的转换使用inet_pton(int af, const char* src, void* dst)，af是地址族，src是原字符串的地址，dst是转换后的二进制地址。
完成地址描述结构体的填充后就可以调用bind进行绑定了，sockfd就是前面创建socket创建出来的fd，之所以是fd（文件描述符）的原因是，linux的思想就是一切皆文件，设备是文件，套接字当然也能是文件，这样就可以忽略其底层的网络细节而将其当作一个文件一样进行读写的操作。传入addr时则需要做一下强转，转成参数中需要的sockaddr结构体指针类型，函数这样的设计和前面构造结构体的使用方式是有原因的，因为bind不是专为ipv4进行服务的，因此要求传入的sockaddr其实更像是一个基类，而使用时可以使用实际需要的子类构造地址信息，然而我们知道c中是没有父子类和继承的概念的，其实库底层结构体定义是通过直接预留空间来实现，子类通过填充来满足结构体大小。len则是地址结构体的大小。
- 绑定后接下来要把fd设置为监听状态，设置后就得到了我们常说的监听fd。使用函数
```listen(int fd, int backlog)```
其中fd是我们要监听的目标fd，backlog的参数含义则是已建立连接的队列的大小，在tcp的三次握手中，客户端一般是主动连接的一端，而服务器是接受连接的一方，当收到syn并返回syn+ack时，这个时候的连接被称为是半连接，半连接队列的大小可以在内核的配置文件中修改，收到客户端的ack后，三次握手结束，这个时候才进入全连接队列。这个全连接队列不意味着可以直接使用其中的连接fd，因为内核并不知道此时用户态是否想处理连接，也不知道是否有空闲线程来处理新连接，因此还需要下一步的accept操作
- accept函数的作用就是从全连接队列中取一个连接出来并返回新的fd，原型
```int accept(int fd, struct sockaddr* addr, socklen_t* addrlen)```
参数fd就是监听socket的fd，后面两个参数一般用于保存连上的客户端的地址信息，一般可以忽略（如果业务无需使用相关信息的话）。函数的返回值就是新建的连接socket的fd。后续和这个客户端的通信就可以通过操作这个fd来实现。
- 前文的操作都是服务器相关的，接下来看下客户端的视角。实际上服务器本身也可以作为客户端连接别的服务器，也就是所谓的服务间通信，实际当然会更复杂一些，可能使用如Kafka、NATS之类的中间件。
```int connect(int sockfd, const struct sockaddr* addr, socklen_t addrlen)```
这个是连接函数的原型，sockfd就是客户端的socket，后面的参数是服务器的地址描述，返回值0表示成功，-1表示失败，connect的底层就是通过发起三次握手和服务器建立tcp连接。

## IO多路复用

前面的socket是网络编程的基础，接下来的IO多路复用则是实际工程的实现和应用的核心
对于每个监听socket（后文统称listen socket），如果每到来一个新的连接socket（后文统称connect socket）都创建一个进程/线程来监听处理，那么整个系统的开销将会快速的上涨，并且如果有一万个连接，分配一万个线程也是不现实的，内存和cpu根本没能力处理这一万个连接的并发。而IO多路复用就是为了实现通过单个线程来同时监听多个fd。
常见的IO多路复用有三种：select、poll、epoll

 - 先说明一下关于阻塞IO和非阻塞IO的定义，以read读取调用为例，阻塞IO当缓冲区没有数据时，cpu会空转占用等待数据到来，而非阻塞IO在缓冲区没有数据时则会直接返回同时设置errno。一般使用IO多路复用时都会把fd设置为非阻塞的，防止出现一个fd卡住整个线程的情况，通过fcntl函数设置其flag为O_NONBLOCK即可
 - select：原理是在用户态下构造需要监听的fd的位图，然后传给内核，内核会先检查一遍是否就绪，没有的话就将进程挂起到等待队列上，进程将会睡眠，某个fd状态变化时内核会唤醒等待的进程，并重新遍历fd集合检查哪些fd就绪
